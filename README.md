# apple-detector

Консольная (CLI) система распознавания образов на Java, которая определяет, изображено ли на фотографии яблоко. Проект выполнен в рамках лабораторной работы №3 по дисциплине «Методы интеллектуальной обработки информации» (Волгоградский государственный университет).

Система построена по итеративной процедуре синтеза системы распознавания: сначала создаётся модель первого приближения (разбиение A1), затем она уточняется (разбиение A2), после чего лучший вариант выбирается по критерию эффективности R.

## Возможности

- распознавание одного изображения с выводом решения и уверенности;
- обучение модели на папках `data/apple` и `data/other` с разбиением выборки на обучающую и тестовую части в соотношении 70/30;
- автоматический выбор рабочего словаря из 4 наиболее информативных признаков и подбор решающих границ;
- оценка модели: матрица ошибок, accuracy, precision, recall и вероятность правильного решения;
- расчёт выигрышей G, потерь ΔG и критерия эффективности R с выбором лучшего разбиения на классы;
- использование только стандартной библиотеки Java (`javax.imageio`, `BufferedImage`); внешние библиотеки подключены лишь для тестов (JUnit).

## Требования

- JDK 21;
- Apache Maven 3.9 или новее (нужен только для компиляции и запуска тестов).

В `pom.xml` подключён `maven-toolchains-plugin`, поэтому для сборки нужен файл `~/.m2/toolchains.xml` с описанием JDK 21. Если такого файла нет, этот плагин можно удалить из `pom.xml`: тогда Maven воспользуется тем JDK, на котором он запущен.

## Запуск

Сборка jar-файла не требуется. Достаточно скомпилировать проект и запустить главный класс из корня проекта:

```bash
mvn compile
java -cp target/classes volsu.Main
```

После запуска программа выводит приглашение `Enter the text:` и ожидает команды. Каждая команда начинается со слова `detect`, например `detect --train data --out models/model_A1.json`. Для выхода нужно ввести `exit`.

Запустить класс `volsu.Main` можно и из среды разработки (Zed, IntelliJ IDEA): команды вводятся в её консоли так же, как в терминале.

Все относительные пути в командах (`data`, `models`, `results`, `test_images`) отсчитываются от корня проекта, поэтому запускать программу нужно именно из него.

## Пример использования

Ниже все команды вводятся в консоли после запуска программы.

### 1. Подготовка данных

Разместите изображения в папках:

```text
data/
├── apple/   # изображения яблок
└── other/   # изображения других объектов (груши, апельсины, мячи, помидоры и т. п.)
```

Поддерживаются форматы JPG, JPEG, PNG, BMP и GIF.

### 2. Обучение модели

Обучение модели для разбиения A1 (первое приближение):

```text
detect --train data --out models/model_A1.json --partition A1
```

Пример вывода:

```text
Модель сохранена: models/model_A1.json; признаки: [colorDominance, roundness, ...]
```

Полный цикл (A1 → A2 → выбор лучшего разбиения по критерию R) запускается значением `ALL`. В этом случае модели сохраняются в папку `models/`, а матрицы ошибок и значения критерия — в папку `results/`:

```text
detect --train data --out models/model_A1.json --partition ALL
```

### 3. Распознавание изображения

```text
detect --image test_images/apple.jpg
```

```text
Яблоко (уверенность 0.92)
```

С указанием модели:

```text
detect --model models/model_A2.json test_images/tomato.jpg
```

```text
Не яблоко (уверенность 0.87)
```

Если уверенность в отрицательном решении низкая (менее 0.55), выводится только `Не яблоко`. Так бывает для объектов, похожих на яблоко (красный шар, помидор).

### 4. Оценка модели

```text
detect --evaluate data --model models/model_A1.json
```

Программа выведет матрицу ошибок, значения accuracy, precision, recall и вероятность правильного решения, а также сохранит матрицу в файл `results/A1_confusion_matrix.csv`.

### 5. Расчёт критерия эффективности

После оценки моделей A1 и A2 (или после обучения с параметром `ALL`) рассчитайте критерий R и выберите лучшее разбиение:

```text
detect --criterion results
```

```text
R(A1) = ...
R(A2) = ...
Лучшее разбиение: ... (R = ...)
```

Файлы `results/gains_G.csv` и `results/R_summary.csv` будут созданы или обновлены.

### 6. Справка и выход

```text
detect --help
exit
```

```text
The end!
```

### Полный сеанс

```text
$ java -cp target/classes volsu.Main
Enter the text:
detect --train data --out models/model_A1.json --partition A1
Модель сохранена: models/model_A1.json; признаки: [colorDominance, roundness, ...]
detect --image test_images/apple.jpg
Яблоко (уверенность 0.92)
exit
The end!
```

## Команды

| Команда | Назначение |
| --- | --- |
| `detect --image <image>` | распознать изображение моделью по умолчанию (`models/model_A1.json`) |
| `detect --model <model.json> <image>` | распознать изображение указанной моделью |
| `detect --train <dataDir> --out <model.json> [--partition A1\|A2\|ALL]` | обучить модель и сохранить её |
| `detect --evaluate <dataDir> --model <model.json> [--partition A1\|A2]` | оценить модель на тестовой выборке |
| `detect --criterion <resultsDir>` | рассчитать G, ΔG и R, выбрать лучшее разбиение |
| `detect --help` | вывести справку |
| `exit` | завершить работу программы |

Пути вида `~/...` раскрываются до домашнего каталога пользователя. Пути с пробелами нужно заключать в двойные кавычки.

## Коды возврата

| Код | Значение |
| --- | --- |
| `0` | успешное выполнение |
| `1` | ошибка ввода: файл не найден, файл не является изображением, неверные параметры, ошибка данных |
| `2` | ошибка модели: файл модели отсутствует, повреждён или не прошёл проверку, либо не удалось сохранить модель |

В интерактивном режиме при ошибке программа выводит сообщение в поток ошибок и продолжает ожидать следующую команду. Код возврата становится кодом завершения процесса, если команду передать аргументами при запуске, например: `java -cp target/classes volsu.Main --image test_images/apple.jpg`.

## Как работает распознавание

### Классы разбиения A1

Множество решений состоит из двух элементов: l1 — «яблоко», l2 — «не яблоко» (k = 2). Первое приближение содержит m = k + 1 = 3 класса:

| Класс | Описание | Решение |
| --- | --- | --- |
| ΩA1_1 | яблоко | l1 — «яблоко» |
| ΩA1_2 | явно не яблоко | l2 — «не яблоко» |
| ΩA1_3 | похоже на яблоко (красные шары, помидоры, частично видимые яблоки) | l2 — «не яблоко», с низкой уверенностью |

### Решающее правило

Для каждого признака рабочего словаря в модели хранятся два вложенных интервала: строгий (характерные значения яблока) и широкий (допустимые значения). В JSON-файле они записаны как `[strictLo, strictHi, looseLo, looseHi]`.

- все признаки лежат в строгих интервалах — класс ΩA1_1;
- хотя бы один признак выходит за пределы широкого интервала — класс ΩA1_2;
- во всех остальных случаях — класс ΩA1_3.

### Уверенность

- для ΩA1_1: `0.6 + 0.4·m`, где m — наименьший нормированный запас до границы строгого интервала;
- для ΩA1_2: `0.6 + 0.4·min(1, 4·d)`, где d — наибольший выход за широкий интервал в долях его ширины;
- для ΩA1_3: значение между `uMin` и `uMax` (по умолчанию 0.3 и 0.5), которое убывает по мере удаления признаков от строгого интервала. Верхняя граница `uMax` калибруется по доле настоящих яблок среди объектов этого класса в обучающей выборке.

### Разбиение A2

Разбиение A2 получается из A1 по алгоритму второго этапа: выбирается класс с наименьшим выигрышем G, после чего его объекты переносятся в тот класс, для которого потеря ΔG минимальна. При обучении только для разбиения A2 (без значения `ALL`) по умолчанию класс ΩA1_3 присоединяется к классу ΩA1_2.

## Признаки

Все признаки вычисляются по маске объекта, а не по всему кадру. Маска строится по отличию цвета пикселей от среднего цвета рамки изображения; из найденных областей выбирается наибольшая, а внутренние отверстия (блики) заполняются.

| Признак | Описание |
| --- | --- |
| `redRatio`, `greenRatio`, `yellowRatio` | доли красных, зелёных и жёлтых пикселей объекта в пространстве HSV |
| `colorDominance` | наибольшая из трёх долей |
| `meanHue`, `meanSaturation`, `meanValue` | средние тон (круговое среднее), насыщенность и яркость |
| `roundness` | округлость контура: площадь маски, делённая на площадь описанного круга |
| `aspectRatio` | отношение ширины к высоте ограничивающего прямоугольника |
| `elongation` | вытянутость: `max(aspectRatio, 1/aspectRatio)` |
| `texture` | средняя амплитуда градиента яркости |
| `brightnessHist0`–`brightnessHist7` | нормированная гистограмма яркости из 8 интервалов |

При обучении информативность признаков оценивается критерием Фишера, `F = (μ₁ − μ₀)² / (σ₁² + σ₀²)`, и выбираются 4 лучших признака. Циклический признак `meanHue` и дублирующий `aspectRatio` из выбора исключаются.

## Метрики качества

Положительным исходом считается решение «яблоко»:

- accuracy = (TP + TN) / (TP + TN + FP + FN);
- precision = TP / (TP + FP);
- recall = TP / (TP + FN);
- вероятность правильного решения — доля верных итоговых решений «яблоко / не яблоко».

При нулевом знаменателе значение метрики полагается равным 0. Кроме бинарной матрицы выводится матрица ошибок по классам разбиения (строки — истинные метки, столбцы — предсказанные классы).

## Критерий эффективности R

Критерий эффективности определяется как математическое ожидание выигрыша:

```text
R = Σ P(Ωi | x) · G(Ωi)
```

В реализации выигрыши и штрафы задаются по умолчанию так:

| Ситуация | Значение |
| --- | --- |
| яблоко распознано правильно | +10 |
| «не яблоко» распознано правильно | +5 |
| ложное срабатывание (не яблоко принято за яблоко) | −8 |
| пропуск яблока (яблоко принято за не яблоко) | −10 |

Вклад класса `G(Ωi)` равен сумме выигрышей и штрафов по матрице ошибок, делённой на общее число объектов. Критерий R равен сумме вкладов всех классов, то есть среднему выигрышу на один объект. Лучшим считается разбиение с наибольшим значением R. Итоговые значения записываются в файл `results/R_summary.csv`, а вклады, штрафы и потери ΔG — в файл `results/gains_G.csv`.

## Тестирование

Запуск всех тестов:

```bash
mvn test
```

Тесты охватывают:

- признаки (преобразование RGB в HSV, доли цветов, округлость, соотношение сторон, время извлечения не более 1 с для изображения 1024×1024);
- решающее правило, диапазон уверенности, сохранение и загрузку модели, обработку повреждённой модели;
- метрики и формат CSV с матрицей ошибок, включая пустую выборку;
- граничные случаи: зелёное яблоко, помидор, красный шар, слабое освещение, несколько объектов, несуществующий файл, файл, не являющийся изображением, изображение больше 1024×1024.

## Ограничения

- Размер входного изображения не должен превышать 1024×1024 пикселей: более крупные изображения автоматически уменьшаются. Перед извлечением признаков изображение приводится к размеру 256×256 пикселей.
- Предполагаемое время обработки одного изображения — не более 1 секунды; при превышении выводится предупреждение.
- Сегментация объекта основана на отличии от цвета фона по краям кадра, поэтому лучше всего система работает на однородном фоне. На сложном фоне маска может охватывать лишние области.
- Если на изображении несколько объектов, решение принимается по наибольшему из них.
- Система опирается на цвет и форму, поэтому похожие по этим признакам объекты (красный шар, помидор) могут относиться к классу ΩA1_3 или ошибочно распознаваться как яблоко.
- Качество модели напрямую зависит от размера и разнообразия обучающей выборки; при малом числе изображений в папках `data/apple` и `data/other` оценки метрик ненадёжны.
- Деление выборки на обучающую и тестовую части фиксировано (зерно генератора 42) либо берётся из файла `python/metadata.csv`, если он существует.
